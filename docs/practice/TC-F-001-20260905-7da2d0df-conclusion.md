## 归因与未确定事项

- **已确定事实：** 提案对象与整数分金额正确，模型自然语言金额错误；该表现与既有 [AQL-001](../defects/AQL-001-amount-unit.md) 一致。本次是独立的新失败样本，发生于正常 chat 场景。未批准、未调用退款/工单写入工具，数据库保持零申请、零工单，源记录不变。
- **待验证假设：** 具体根因尚未确定。现有证据不能区分提示词、工具字段/单位表达或模型输出等因素的影响；不将任何一种推测写为已确认原因。
- **缺少哪些证据：** 本地 YES 确认、批准后创建申请、工单关联及最终完成回答的证据均未产生，原因是用例按金额冲突规则停止。也没有修复对照实验、重复试验稳定性或真实支付链路证据。金额错误和停止时零写入的证据已具备。
- **下一步最小验证：** 基于本次事件 3/8/9 追踪金额字段到用户回答的传递，明确待验证因素后再单因素复测；复测另用新会话与新目录保留全部结果。本次整理未执行定位、修复或复测。

记录整理过程中还出现过链接校验器误报、文件工具环境错误、导出命令过长和文档未更新校验失败，随后修正并完成文件核对；这些与被测业务金额错误分开记录。原始命令及错误保存在[整理操作日志](../../evidence/2026-09-05/tc-f-001-7da2d0df/artifact-operations.json)，未因这些错误重新运行模型。

## 本用例结论

- **业务状态：** 确认前零写入、源记录保护通过；正常申请终点未到达，确认后状态未执行。
- **工具调用与确认：** 本轮查询和提案共 4 次工具调用，均返回 ok=true；批准及批准后创建顺序未执行，不能宣称完整确认流程通过。
- **最终回答：** 首轮金额表述失败；批准后的完成回答未执行。未观察到虚构退款到账。
- **本用例综合结论：失败。** 模型将应为 100.00 CNY 的金额表述为 10000 CNY，触发用例步骤 3 的暂停批准条件。后续步骤标记未执行，不计通过。
- **证据完整性/参考等级：** 已有首轮原始报告、直接数据库快照、调用轨迹及命令输出，支持本次金额错误和零写入结论；仅模拟范围内参考 B 级。本项目不具备真实支付链路证据，不代表正常全流程通过。
- **未覆盖：** 本地批准和正常写入终点、只读角色、跨租户请求、主动跳过确认、幂等/超时、工单失败、其他支付边界、模型异常及性能。
