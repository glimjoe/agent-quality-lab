# 项目计划

状态：首条流程已实现，采用 Python + SQLite + DeepSeek；已建立工程测试与真实模型的小样本基线，详见[验证报告](verification-2026-09-05.md)。后续阶段仍是计划。

## 目标与成功标准

目标是积累能够支持 Agent 应用测试转岗的实际能力和可展示证据。用户已有 B/S、SaaS、移动应用及功能、性能、白盒、黑盒测试经验，目前没有目标岗位 JD，Java、Python、Go 均可使用。

完成项目时，参与者应能独立说明并用仓库材料证明：

1. 如何把自然语言任务转成可验证的目标与约束。
2. 如何检查最终结果、工具调用过程和非预期副作用。
3. 如何区分需求、检索、模型决策、工具实现、运行环境和评测器自身的问题。
4. 如何通过重复实验判断稳定性，并解释样本量与结论的限制。
5. 如何评估一次变更对任务成功、安全约束、延迟和成本的影响。

这些是项目验收目标，尚未验证达成；不构成岗位录用保证。

## 建议的阶段交付

| 阶段 | 主要工作 | 完成证据 |
|---|---|---|
| 0：确定第一条流程 | 对齐岗位方向、实现分工、业务规则、环境和模型预算 | 已确认的需求、规则示例、风险与验收标准 |
| 1：跑通一个 Agent | 最小交互入口、一个 Agent、必要工具、模拟数据库、调用记录与数据重置 | 从干净数据执行任务，能追踪实际工具调用和业务变化 |
| 2：建立质量基线 | 人工设计种子用例、确定性断言、真实模型评测、异常注入 | 可执行命令、用例结果、缺陷报告和修复回归 |
| 3：做一次可解释的改进 | 改提示词、工具描述或检索策略中的一个因素，比较前后版本 | 固定评测条件、重复运行、失败分析与留出集结果 |
| 4：整理 GitHub 作品 | 复现说明、架构图、演示、实验报告、局限和贡献说明 | 他人按 README 能运行核心流程并检查证据 |

不预设工期；投入时间和编码熟练度尚未确认。

## 能力迁移

| 已有测试经验 | Agent 场景中的练习 |
|---|---|
| 需求与功能测试 | 模糊表达、信息不足、多轮修改目标、合理拒绝和转人工 |
| 接口测试 | 工具选择、参数语义、契约错误、工具返回的理解 |
| 数据与状态测试 | 最终状态、幂等、部分失败、无关数据是否被修改 |
| 权限与多租户测试 | 越权尝试、后端拦截、检索隔离、会话串扰 |
| 白盒测试与定位 | 基于可观察的输入、输出、调用和状态变化定位失败 |
| 性能与可靠性测试 | 完成时间、调用次数、成本、成功率、限流与依赖故障 |
| 自动化回归 | 模型、提示词、工具和知识库变更后的行为回归 |

## 实现边界建议

- 第一版采用单 Agent、Python 标准库、SQLite 与 CLI；模型服务为 DeepSeek。
- 模型参与意图理解、工具选择、信息澄清及结果解释。
- 鉴权、金额计算、状态约束、幂等、重试上限和确定性数据转换由普通代码实现。
- 后续按新增风险选择知识检索、上下文管理、MCP、浏览器操作或多 Agent 协作；每次增加组件都说明测试目的。
- 第一版使用模拟数据和模拟业务服务。模型服务和本轮预算已确认；后续实验先固定样本与次数再运行。

## 训练分工建议

以下为提案，具体编码分工在了解熟练度后确定。

- 项目参与者负责风险判断、预期结果、测试设计、缺陷分析和质量结论，并能够解释采用的评测器。
- AI 协助搭建应用、生成候选材料、实现经审查的重复性代码和提供评审反馈。
- 安排部分盲测练习：测试前不公开注入故障的位置，完成后揭示并复盘。
- 同一模型生成的实现、测试与评分结果，不自动视为相互独立的证据；关键规则由人工核对，确定性结果由代码检查。

## 评测与报告约定

- 每个任务记录初始数据、用户目标、允许和禁止的操作、预期结果以及证据来源。
- 工程测试可使用固定模型响应；真实模型评测单独运行并标注，二者分别报告。
- 每次试验重置业务数据和会话状态；固定模型配置不等于保证输出完全确定。
- 任务成功由任务目标与必要约束共同决定。安全违规单独报告，不能被平均分掩盖。
- 记录非法调用尝试与实际越权结果；后端拦截成功不能掩盖 Agent 的行为问题。
- 有多种有效路径时只约束必要动作和顺序，不把唯一参考轨迹当成唯一正确解。
- 调试集与留出评测集分开；反复用于调优的样本不能继续充当未见样本。
- 重复次数、样本量和阈值在相应实验前确定；报告实际分子、分母和失败类型。
- 主观评分可使用模型辅助，但需人工标注样本校准；状态、数量和权限等结果优先用程序断言。
- 运行记录包含版本、配置、数据集、次数、用时和调用成本。缺失项明确标为未采集。
