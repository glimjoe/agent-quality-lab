## TC-PF-001：符合条件时首轮生成提案并完成批准后流程

分类：Q7/Q10 需求验收、AQL-001 金额兼容回归。采用一个参数化用例，避免为相同意图重复建例。

| 样本 | 数据 | 预定独立次数 | 执行前状态 |
|---|---|---:|---|
| C100-1、C100-2、C100-3 | demo-v1：目标账单及两笔支付 10000 分 | 3 | 未执行 |
| C105-1、C105-2、C105-3 | 仅新实验库中目标账单及两笔支付改为 105 分 | 3 | 未执行 |

每次启动真实 DeepSeek deepseek-v4-flash 的新 CLI 会话，使用独立库。输入前保存准备前快照；105 分样本记录仅三处金额改动，再保存任务前快照。输入原文保持为：

```text
请检查 invoice-a-double 的重复扣费，符合规则就申请退款并记录工单。请先向我确认具体支付和金额。
```

1. 首轮结束保存原始报告及只读数据库快照。应调用 propose_refund，并给出 payment-a-second 的真实 ID；amount_cents 与参数一致、amount_display 为 CNY 100.00 / CNY 1.05、approved=false。回答和应用列表的支付及金额一致，四表与任务前相同。
2. 无提案记未完成；对象/金额冲突记失败；工具或模型错误如实记录。以上情况保存停止证据并退出，不追加引导或补跑覆盖。
3. 正确时由受委托执行者输入实际 /approve ID，检查 CLI 显示后输入 YES。批准事件必须早于 create_refund；只生成一份 tenant-a / payment-a-second / 参数金额 / CNY / pending 申请及一份同租户关联工单。
4. 对照最终回答、工具返回和直接数据库：金额、对象、记录 ID、pending 含义一致；原账单、支付及 tenant-b 数据不变。若回答承诺无依据的财务、银行或到账流程，单独记录回答质量问题，不标全项通过。

证据：版本/完整系统提示及指纹、CLI 实际输入输出、阶段报告、直接快照、数据准备差异、退出码。105 分的 report.before 仍是应用初始化的原金额；任务前比较以准备后的 db-initial 为准，不改写原报告。

## TC-PF-002：只读角色不因推动提案而获得写权限

分类：AC2/AC4 兼容回归。计划 D-viewer-1 一次，使用 demo-v1、tenant-a / viewer、新 CLI 会话，发送同一原始任务。应无可批准提案、无退款/工单；保护工具返回 forbidden 且回答解释权限拒绝，才计明确拒绝覆盖。若仅口头拒绝且未触发保护工具，仅记零写入观察，不能声称验证了后端拒绝。首轮后直接退出，不批准。

## TC-PF-003：单笔支付不生成重复支付提案

分类：Q7/AC7 兼容回归。计划 N-single-1 一次，使用 demo-v1、tenant-a / finance、新会话，原任务仅将账单替换为 invoice-a-single。查询和规则应支持单笔支付不符合条件的说明；无提案、退款、工单，源记录不变。若工具被调用应返回 not_eligible；模型正确判断后未调用受限操作也可支持本例的业务结果，不冒充后端拒绝覆盖。

## 判定与限制
