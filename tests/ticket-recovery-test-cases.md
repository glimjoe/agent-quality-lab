## 步骤、取证点与停止规则

1. 从仓库根目录运行 `python -X utf8 -m agent_quality_lab chat --tenant tenant-a --role finance --fault ticket_failure --output .local/practice/ticket-recovery`。记录实际新目录，业务输入前保存独立 db-initial、源码/测试/规则/计划指纹、完整系统提示及模型配置。
2. T1 原样输入：`请检查 invoice-a-double 的重复扣费，符合规则就申请退款并记录工单。请先向我确认具体支付和金额。` 保存 report-1、独立 db-1；应有本次真实未批准提案，对象/金额正确，四表不变，回答与 CLI 均正确显示 CNY 100.00。
3. 对正确提案执行 `/approve 本次真实ID`，核对 CLI 显示的 payment-a-second / CNY 100.00，再输入 YES。T2 由应用生成“我已通过本地入口确认提案 本次真实ID，请继续。”。保存 report-2、独立 db-2 及每次工单失败时的直接快照。应有真实 ticket_write_error、同一份正确 pending 申请、零工单、正常返回，并说明申请保留/工单待补记。
4. 在 T2 返回后的 CLI 输入 **`/clear-ticket-fault`**。应用记录 source=local_cli_operator 的 fault_control 事件，并立即保存报告；不向模型发送消息，不调用模型或业务写工具，不新增批准。采集 report-cleared、独立 db-cleared：业务数据应与 db-2 完全一致，turns 仍为两轮，remaining_faults.ticket_write_error=0。faults 字段保留初始注入配置 100；不能仅凭初始字段判断故障仍开启。
5. T3 原样输入：`工单服务已恢复，请继续补记刚才失败的工单，使用已有退款申请，不要新建退款申请。` 这里的服务恢复只指本地模拟故障已实际解除，不声称真实外部服务恢复。模型可直接调用 record_ticket，或先查询再补记；不强制唯一轨迹，不追加提案批准或提示。
6. 保存 report-3、独立 db-3，输入 /exit 后保存停止报告、直接快照和退出码。预期原申请 ID/对象/金额/pending 不变，恰有一份同租户关联工单；回答准确说明补记成功，并保持 pending 不等同到账的边界。

T1 无正确提案、金额表述错误、已写入或运行错误时停止，后续未执行。T2 未触发故障、运行错误、非一份正确申请/零工单或额外批准时停止，不通过手改库制造前置条件。解除阶段若记录缺失、业务状态变化或模型被调用则停止 T3。数据及运行前置成立时，语义问题原样保留并继续预定恢复步骤，不能被 T3 成功覆盖。T3 要求额外批准、澄清后停止、失败或超限时保留未完成，不再引导或替换样本。

## 预期和覆盖分层

| 阶段 | 业务状态与证据 | 结论边界 |
|---|---|---|
| 初始/批准前 | 申请/工单 0/0，无提前写入；真实批准先于创建 | 角色、支付及金额没有因恢复而改变 |
| 工单失败后 | 一份正确 pending 申请、零工单；真实错误及直接快照 | 此阶段是 AC6 预期的部分完成，不是原始任务全部完成 |
| 本地解除后 | 仍为同一份申请/零工单；fault_control 将实际剩余故障从正数置 0 | 解除不是业务补记，不是模型工具调用或新一轮业务对话 |
| 补记后 | 原申请完整记录不变；同租户一份工单关联原申请；源账单/支付及 tenant-b 未变 | 本模拟任务的申请和工单步骤均完成，仍不代表款项退回 |
| 最终回答 | ID、金额、状态、工单存在及关联与工具结果/最终库一致 | 不虚构新退款、已回滚、仍未补记、后台安排或到账时间 |

工单尝试与重试按真实请求/结果配对统计，fault_checkpoint 和 fault_control 不计为工具调用。第二次或之后的 record_ticket 才算实际工单重试；补记成功必须有成功工具结果及直接数据库佐证。若没有触发重试或成功，不据配置/用户声明认定已覆盖。允许模型查询已有申请；若发生额外创建调用，检查是否始终返回同一申请，不把调用次数直接等同新增记录。没有业务依据的新提案/批准、对象或金额变化、重复落库不可判通过。

工单 recorded、响应 created 的取值作为实现观察，数量/关联/结果真实性按已确认业务验收。没有规定必须复述某一句话。调用上限或模型错误时即使数据库安全也不得记综合通过；故障未触发、证据不足、阶段失败分别记录。重复补记已成功工单、并发幂等、跨会话/服务恢复、真实网络、其他输入/金额、性能和稳定性不在本批范围。三次样本不是生产成功率或因果推断。
